# 마이그레이션

이 디렉터리의 `*.sql`은 배포 시 `scripts/run_migrations.py`가 **파일명 순으로** 자동 적용한다
(`.github/workflows/ci.yml`의 `deploy` job). 적용된 파일명은 DB의 `schema_migrations` 테이블에
기록되어 두 번 실행되지 않는다.

## 새 마이그레이션 추가

파일 하나 만들어 머지하면 끝이다. EC2에 접속할 일은 없다.

```
scripts/migrations/YYYY-MM-DD_설명.sql
```

- **파일명에 날짜 접두사를 붙인다.** 적용 순서가 파일명 순이다.
- 파일 하나가 한 트랜잭션이다. 실패하면 롤백되고 기록도 남지 않아 다음 배포에서 다시 시도한다.
- 여러 문장은 `;`로 구분한다. 러너가 분리해서 실행한다.
- 문자열 리터럴 안에 `;`가 필요하면 그 문장만 별도 파일로 분리할 것 — 러너의 분리가
  리터럴을 고려하지 않는다.

## 왜 Alembic이 아닌가

`scripts/create_tables.py`의 `create_all`은 없는 테이블만 만들고 기존 테이블에 컬럼을
추가하지 않는다. 그 간극만 메우면 되는 규모라 도구를 도입하지 않았다. 스키마 변경이
잦아지면 재검토할 것.

## 현재 상태

적용 대기 중인 파일은 없다. 2026-08-21의 `source_locale` 마이그레이션은 AI 출력 언어를
영어로 고정하고 번역을 FE 온디바이스로 옮기기로 결정하면서 해당 컬럼이 불필요해져 제거했다.

이미 프로덕션에 그 컬럼이 적용된 경우 **남겨둬도 무해하다** — `NOT NULL DEFAULT 'ko'`이므로
컬럼을 명시하지 않는 INSERT도 통과한다. 굳이 DROP하지 않는다.
